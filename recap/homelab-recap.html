From a password manager to a live website

In one day we set up a safe place for secrets, locked down the domain on Cloudflare, put a reverse proxy with a real certificate on the Chromebook, and made a test page reachable from anywhere on the internet without opening a single port on the home router.

The big picture

How a visitor reaches the site

Someone types hello.example.com. Cloudflare answers, handles the secure connection, and passes the request down a tunnel that the Chromebook itself opened from the inside. Traefik, the "front desk" program, looks at the name and hands the request to the right app.

a web request the tunnel (encrypted)

The router never forwards anything. The Chromebook calls out to Cloudflare and keeps that line open, so visitors' requests ride back down it.

What we did, in order

The day, step by step

  1. Picked 1Password and made a Homelab vault

    A 1Password Individual account (about $36/yr after the trial; Bitwarden is a free alternative), the desktop app, and its command-line tool op. Old logins from another password manager were copied over by hand, so no unencrypted export file ever touched the disk.

    Why: every token and password gets one home.

  2. Made a Cloudflare DNS token and stored it

    Token traefik-dns can only edit DNS records for example.com. You pasted it into 1Password. Claude tested it without ever seeing it.

    Why: Traefik needs it to prove to Let's Encrypt that we own the domain.

  3. Stopped the constant PIN prompts

    Every command Claude runs looked like a new window to 1Password, so Windows Hello kept asking. A service account that can only see the Homelab vault fixed it. Your Personal vault stays out of reach.

    Why: far fewer interruptions. The trade-off: any program running as that Windows user can use the Homelab vault. A YubiKey would not have helped here.

  4. Locked down the domain's security settings

    In Cloudflare: encryption mode Full (strict), Always Use HTTPS on, oldest allowed TLS version 1.2. HSTS was left off on purpose because it is hard to undo.

    Why: visitors always get an encrypted connection, and Cloudflare insists on a real certificate at home too.

  5. Started Traefik and got a real certificate

    Traefik and a tiny test app (whoami) run in Docker on the Chromebook. It got a practice certificate from Let's Encrypt's test server first, then the real one: valid until 6 Feb 2027 and renewed automatically.

    Why: one program handles HTTPS for every app we add later.

  6. Opened the Cloudflare Tunnel

    You created tunnel chromebook and saved its token. Claude started the cloudflared container, then added the public route in your Chrome. The site answered from the internet with a valid certificate.

    Why: public access with no port forwarding and your home IP hidden.

  7. Wrote everything down and committed it

    Plan, inventory, decision records, how-tos, the stack config and helper scripts all went into a git repo. A scan before each commit confirmed no secrets went in.

Certificates

How Traefik proves it owns the domain

Let's Encrypt only hands out a certificate to whoever controls the domain. Instead of letting Let's Encrypt connect to your house, Traefik proves control through Cloudflare's DNS. That is the "DNS challenge".

  1. Traefik asks Let's Encrypt for a certificate

    For hello.example.com.

  2. Let's Encrypt replies with a puzzle

    "Put this exact text in a DNS record called _acme-challenge.hello.example.com."

  3. Traefik uses the DNS token to add that record in Cloudflare

    This is the only thing the token is allowed to do.

  4. Let's Encrypt checks the record, then issues the certificate

    Traefik removes the temporary record and stores the certificate in letsencrypt/acme.json. It repeats this about 30 days before expiry.

Words you'll see

Plain-language glossary

Reverse proxy (Traefik)
A front desk. Every web request arrives here first and gets sent to the right app by its name.
Container (Docker)
An app packaged with everything it needs, so it runs the same anywhere and is easy to start, stop or delete.
Cloudflare Tunnel
A private line the Chromebook dials out to Cloudflare. Visitors' requests come back down it, so the router stays closed.
DNS
The internet's phone book: turns a name like example.com into an address.
Certificate (TLS/HTTPS)
The padlock in the browser. Proves the site is really example.com and encrypts the connection.
Full (strict)
Cloudflare only talks to your server if your server shows a real, valid certificate.
SNI, "Match SNI to host"
The site name sent at the start of a secure connection. Matching it tells Traefik which certificate to show.
API token
A password for a program, limited to specific jobs. Ours can only do one thing each.
Service account
A 1Password login for a program instead of a person, limited to one vault.
Staging (Let's Encrypt)
A practice server that gives fake certificates, so mistakes don't hit the real limits.
Lessons

Things that tripped us up

Each of these cost a few minutes today. They're also written into the how-tos.

Cloudflare hides the tunnel token with asterisks
Click the eye icon to reveal it before copying. A 32-character "token" means you copied the masked one; the real one is about 184.
Closing the Claude window doesn't quit it
It keeps running in the system tray. Right-click the tray icon → Quit, so new settings (like the service account) take effect.
Script "does not exist" in PowerShell
The terminal was in your home folder, not the repo. Use the full path to the script.
The browser pane froze on pop-ups
Cloudflare opens pop-up windows that block the pane. We now use Claude in Chrome for Cloudflare.
op run -- failed in Windows PowerShell
PowerShell 5.1 swallows a bare --. Write it as '--'.
The Chromebook's shell is fish, not bash
Copy bash scripts over and run them with bash script.sh instead of typing bash syntax over SSH.
Checking on it

Is it still working?

From the PC. You should see HTTP/1.1 200 and Server: cloudflare.

curl.exe -sS -D - https://hello.example.com -o NUL

Containers on the Chromebook. All three should say "Up".

ssh chromebook "docker ps --format '{{.Names}} {{.Status}}'"

Is the Cloudflare DNS token still valid? Read-only, and the token is never shown.

powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\test-cloudflare-token.ps1

Take everything offline (config, tokens and certificate stay on disk). Start it again with docker compose up -d.

ssh chromebook "cd /opt/stacks/proxy; docker compose down"
